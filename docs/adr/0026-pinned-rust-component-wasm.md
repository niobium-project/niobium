# ADR-0026: Pinned Rust for Component Wasm

- **Status:** Accepted
- **Date:** 2026-10-09
- **Amends:** [ADR-0023](0023-standard-content-and-component-contracts.md) (decision 4, Component implementation language)

## Context

The Component profile uses upstream WIT tooling and the Canonical ABI. Its
qualified host is the pinned Wasmtime Component C API with Pulley.
Repository-owned libraries, including the official files library, are Rust
guests generated by `wit-bindgen`.

Zig remains the language of the compiler, worker, journal and host.
[ADR-0023](0023-standard-content-and-component-contracts.md) permits pinned
Rust for this integration and refuses a custom ABI when qualification fails.
Core Wasm interpreters, without Component support, do not implement
the Canonical ABI.

A Zig engine or guest that defines its own memory layout would be that custom
ABI. Binary size and a Zig-only source build are real costs of the Rust pin.
Those costs leave the Canonical ABI, fuel limits and consumer evidence
unchanged.

## Decision

1. Wasmtime, `wit-bindgen`, `wasm-tools` and capability libraries maintained
   in this repository use the pinned Rust implementations. The qualified
   versions live in [capability library v2](../spec/capability-library.md)
   and the [Wasmtime provenance record](../../third_party/wasmtime/PROVENANCE.md).
2. A competing alternative is an upstream Component implementation with the
   same Canonical ABI. It disables ambient WASI, native JIT, guest threads and
   untrusted engine artifacts, and it meets the existing execution, allocation
   and consumer evidence. Adopting it requires a later ADR that names the
   implementation and that evidence.
3. This repository does not write a replacement Canonical ABI or Component
   engine to remove Rust. A missing competing alternative leaves the pinned
   Rust stack in place.
4. The independent C qualification consumer remains evidence for the same
   contract. The engine and repository-owned libraries stay on the Rust
   implementations.
5. Product and third-party libraries may use another upstream guest generator.
   The result must be a standard Component under the same contract.
6. Author-language
   packages, including a future Rust author SDK, stay on the frontend contract.

## Consequences

Source builds keep the pinned Rust toolchain and the `wasm32-unknown-unknown`
target for the engine and repository guests. Product assembly copies a
published runtime and does not compile the Component engine.

A change of engine or of a repository-owned guest waits for the competing
alternative and its ADR. The capability-library contract continues to name
the qualified versions.
